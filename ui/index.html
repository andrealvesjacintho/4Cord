4Cord

4
Central de informações4Cord v2.4.0

O 4Cord é um cliente de conversa leve para Linux, feito para ler canais de texto e mensagens diretas com uma interface compacta e própria. Ele conversa diretamente com a API e o gateway do Discord; o aplicativo web do Discord não é carregado.

Criador Guaxi Rascal idealizador e desenvolvedor do projeto 4Cord
O 4Cord é uma recriação leve inspirada em aplicativos de comunicação. Ele não é uma implementação oficial do Discord e não tem vínculo, patrocínio ou aprovação da Discord Inc.

Pontos positivos

  • Interface compacta: mensagens em poucas linhas, sem fotos de perfil nas mensagens.
  • Histórico limitado a 300 mensagens por conversa no DOM e na memória, com paginação de 50 em 50.
  • Mídia só é baixada depois do clique e é liberada quando sai da tela; emotes externos não são carregados.
  • Lista de servidores simplificada, com preferência pelo servidor NOTES quando ele existe.
  • Recursos úteis no dia a dia: DMs, canais de texto, reações, componentes interativos, anexos, temas e cor de destaque.
  • Interface feita com HTML, CSS e JavaScript próprios, usando o GTK e o WebKitGTK já presentes no sistema — sem framework JavaScript externo.
  • Indicador de RAM do processo e um log de diagnóstico que não registra o conteúdo das mensagens.

Limitações e pontos negativos

  • Não oferece voz, vídeo, compartilhamento de tela, threads, busca, notificações do sistema, enquetes, gerenciamento de servidores ou moderação.
  • O Markdown é simplificado e embeds, perfis completos e emotes personalizados não são exibidos como no cliente oficial; emotes externos aparecem como ?.
  • O login é feito por token de conta, não por OAuth. O token vale como uma senha e fica gravado localmente sem criptografia (com permissão restrita).
  • Depende da API, do gateway e do CDN do Discord, além de conexão com a internet. Mudanças no serviço podem quebrar o aplicativo.
  • É um aplicativo para Linux; não há versões para Windows, macOS ou celular.
  • A janela mantém até 300 mensagens por conversa. Mensagens antigas ficam no servidor e são carregadas sob demanda; não há modo offline.
  • Após uma reconexão, o 4Cord tenta recuperar as mensagens disponíveis na API, mas o Discord pode não conservar ou entregar eventos que ficaram fora do alcance da sessão.
  • Os testes automatizados usam dados simulados; o CDN real, uma conta real e o Arch Linux com Xfce4 ainda dependem de validação manual neste ambiente.

Resumo das principais etapas verificáveis do projeto, sem datas inventadas. A ordem abaixo segue a evolução descrita na documentação e no código.

  1. Origem como TrashPanda. O aplicativo começou com outro nome e uma configuração local própria.
  2. Identidade 4Cord. Nome, ícone, atalho e configuração passaram a usar 4Cord. A migração do diretório antigo é feita uma única vez e preserva os arquivos originais.
  3. Interface própria e compacta. A UI deixou de depender do aplicativo web do Discord e adotou mensagens compactas, sem avatares nas mensagens, com temas escuro, AMOLED e automático, além de cor de destaque configurável.
  4. Simplificação da navegação. A lista de servidores foi reduzida ao seletor necessário, com preferência pelo servidor NOTES quando presente, e as DMs ganharam uma lista dedicada.
  5. Auditoria de desempenho. Foram implementados o limite de 300 mensagens, o cache de 1000 IDs vistos, miniaturas sob demanda, liberação de mídia fora da tela, log crítico por padrão e desativação explícita do corretor.
  6. Versão 2.4.0 para distribuição. Foram adicionados instalador compartilhado, launcher, requisitos documentados e instruções para Ubuntu e Arch Linux.
  7. Recuperação de DMs e central de informações. A reconexão passou a sincronizar a conversa atual e a recuperar mensagens perdidas quando a API permite; o botão de ajuda reúne a documentação do projeto.

Resumo das tecnologias usadas para construir e executar o 4Cord. Os detalhes de arquitetura ficam em Detalhes avançados.

Janela e sistemaPython 3 com PyGObject, GTK 3 e GdkPixbuf.
ComunicaçãoAPI REST v9 e gateway WebSocket v10 do Discord.
Dependências PythonSomente bibliotecas padrão e o PyGObject fornecido pela distribuição; não há pacotes PyPI obrigatórios.
ArmazenamentoConfiguração local em JSON e token em arquivo com permissão restrita.

O 4Cord não carrega o cliente web do Discord, não inclui telemetria própria e não usa bibliotecas JavaScript externas.

Arquitetura

Um único código-fonte atende Ubuntu e Arch Linux. A interface é uma página local carregada no WebKitGTK; ela conversa com o Python por uma ponte de mensagens JSON. O Python concentra a janela GTK, as configurações, os comandos e a comunicação com o Discord.

  • app.py: janela GTK, identidade, login nativo, configurações, atalho .desktop, indicador de RAM, ponte JavaScript-Python e comandos.
  • core/discord.py: cliente REST v9, gateway, upload multipart, reações, interações e reconexão.
  • core/ws.py: WebSocket RFC 6455 mínimo, escrito apenas com a biblioteca padrão, com suporte a frames, ping/pong e fechamento.
  • core/log.py: log crítico por padrão, modo detalhado opcional, rotação e redação de credenciais.
  • ui/: HTML, CSS e JavaScript da interface; sem bundler e sem dependências de frontend.

Comunicação e sincronização

  • REST em /api/v9 para usuário, servidores, canais, DMs, mensagens, reações, interações e envio de arquivos.
  • Gateway WebSocket v10 com IDENTIFY, RESUME, heartbeat, backoff e códigos de fechamento fatais.
  • Cada reconexão usa uma nova conexão WebSocket e um novo Event de heartbeat; conexões e listeners antigos são encerrados para não duplicar eventos.
  • Na reconexão, a conversa atual busca até 100 mensagens recentes para detectar sobreposição e evitar buracos. IDs já vistos são deduplicados.
  • DMs conhecidas são atualizadas com GET /channels/{id}/messages?after=... quando a API informa mensagens novas; a recuperação é limitada a uma página por reconexão e não cria uma segunda conexão de eventos.
  • O botão de recarregar no cabeçalho força a sincronização da conversa atual, seja canal de servidor ou DM, e atualiza a lista de DMs.
  • A janela mantém no máximo 300 mensagens, páginas de 50 e cache de 1000 IDs. Mensagens perdidas durante uma desconexão só podem ser recuperadas se o Discord ainda as disponibilizar.

Configuração, dados e segurança

  • Configuração em ~/.config/4cord/settings.json; token em ~/.config/4cord/token; log em ~/.config/4cord/log.txt.
  • Token, configurações e log são criados com permissão 600. O log rotacionado também recebe essa permissão.
  • O token não é gravado no código, no README nem no log. Ainda assim, ele fica em texto simples no disco: quem tiver acesso à conta do usuário pode lê-lo.
  • O importador opcional procura uma sessão do Discord nos armazenamentos locais de navegadores conhecidos. Ele não envia esses dados para outro lugar além da API do Discord.
  • A migração de ~/.config/trashpanda é única, não apaga o diretório antigo e não restaura um token removido no logout.
  • O armazenamento localStorage guarda apenas cache visual (tema, acento, largura e preferências), não credenciais.

Desempenho

  • Limite de 300 mensagens no DOM e na memória; cache de 1000 IDs vistos; páginas de 50; sincronização de reconexão de até 100.
  • Miniaturas de anexos do CDN do Discord sob demanda, com fallback para a URL original; visualizador sempre usa a imagem original.
  • Um único IntersectionObserver libera a mídia revelada que sai da tela, mantendo apenas o nó aberto no visualizador.
  • Log detalhado desligado por padrão; RAM lida de /proc com PSS agregado dos processos do 4Cord e fallback para RSS.
  • Recursos do WebKit sem WebGL, WebAudio, aceleração de hardware ou corretor ortográfico, reduzindo dependências e consumo.

Compatibilidade

  • Testado nesta etapa no Ubuntu 26.04 com GNOME. O Arch Linux com Xfce4 possui instruções e pacotes documentados, mas a validação depende de um ambiente Arch disponível.
  • Não há dependência obrigatória de GNOME: em outros ambientes o tema é lido do GTK; o gsettings do GNOME é usado apenas em sessões GNOME, Unity ou Ubuntu com GNOME.
  • O indicador de RAM usa /proc, portanto o aplicativo é específico para Linux.
  • O atalho 4cord.desktop usa StartupWMClass=4cord e funciona em GNOME e Xfce4; o lançador respeita um ambiente virtual local quando ele existe.
  • Os testes automatizados usam o modo --mock; isso não substitui uma conta real, o CDN real ou uma instalação limpa de Arch Linux.
